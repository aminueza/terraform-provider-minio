# minio_sts_credentials (Ephemeral Resource)

Obtains temporary MinIO credentials through STS AssumeRole. The credentials are never written to Terraform state: use them to configure another provider or to feed a write-only attribute.

Ephemeral resources are evaluated during every Terraform operation and their results are never persisted to state or to the plan file. That makes them the right place for credentials the provider mints: the value reaches whatever consumes it, and nothing is written to disk.

Requires Terraform 1.10 or later.

## Example Usage

```terraform
ephemeral "minio_sts_credentials" "scoped" {
  session_name     = "terraform-scoped"
  duration_seconds = 3600

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject", "s3:PutObject"]
      Resource = ["arn:aws:s3:::uploads/*"]
    }]
  })
}

provider "minio" {
  alias = "scoped"

  minio_server        = var.minio_server
  minio_user          = ephemeral.minio_sts_credentials.scoped.access_key
  minio_password      = ephemeral.minio_sts_credentials.scoped.secret_key
  minio_session_token = ephemeral.minio_sts_credentials.scoped.session_token
}
```

Ephemeral values can only flow into provider configuration, other ephemeral resources, and write-only attributes. Terraform rejects a configuration that assigns one to a regular resource attribute or output.

## Requirements and behavior to plan for

The provider this resource reads from must use static credentials. The AssumeRole request is signed with `minio_user` and `minio_password`, so a provider scoped down through `assume_role` or `assume_role_with_web_identity` would not constrain the credentials this resource issues. The resource refuses to run in that case rather than silently widening the scope. The same applies to a provider authenticated with `minio_session_token`: MinIO rejects AssumeRole requests made with temporary credentials, so this resource cannot be chained.

Terraform opens an ephemeral resource on every operation, including `plan`. Each open mints a new session on the server, and MinIO keeps it until it expires. A pipeline that plans frequently therefore accumulates temporary sessions, each living at least the `duration_seconds` minimum of one hour. They expire on their own; nothing needs to be cleaned up, but the count is visible in `mc admin accesskey ls --temp-only`.

## Schema

### Optional

- `duration_seconds` (Number) Lifetime of the returned credentials in seconds. Defaults to 3600, which is also the minimum: the MinIO client library replaces any lower value with 3600, so shorter lifetimes are rejected here rather than silently ignored.
- `external_id` (String) External ID for cross-account role assumption.
- `policy` (String) IAM policy in JSON format that scopes down the permissions of the returned credentials.
- `role_arn` (String) ARN of the role to assume. MinIO accepts an empty value and derives the policy from the requesting user.
- `session_name` (String) Session name for the assumed role. Defaults to `terraform`.

### Read-Only

- `access_key` (String) Access key of the temporary credentials.
- `expiration` (String) Time at which the credentials stop being valid, in RFC 3339 format. Null when the server does not report an expiry.
- `secret_key` (String, Sensitive) Secret key of the temporary credentials.
- `session_token` (String, Sensitive) Session token that must accompany the temporary credentials.
