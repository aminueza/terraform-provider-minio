# minio_notify_nsq (Resource)

Manages an NSQ notification target for MinIO bucket event notifications.

**NOTE:** Creating a new notification target may require a MinIO server restart before it becomes fully active. The `restart_required` attribute indicates when this is necessary.

**NOTE:** MinIO applies a new notification target only after a restart, so Terraform cannot tell on create whether a target with the same name is already stored on the server. Creating this resource over an existing target merges into it and takes it over, and destroying the resource then deletes it. Check first with `mc admin config get <alias> notify_nsq`, and import an existing target instead of creating it. See [#1438](https://github.com/aminueza/terraform-provider-minio/issues/1438).

## Example Usage

```terraform
resource "minio_notify_nsq" "events" {
  name         = "primary"
  nsqd_address = "nsqd.example.com:4150"
  topic        = "minio-events"
}
```

- `name` (String) Target name identifier.
- `nsqd_address` (String) NSQ daemon address (e.g., 'localhost:4150').

### Optional

- `comment` (String) Comment or description for this notification target.
- `enable` (Boolean) Whether this notification target is enabled.
- `queue_dir` (String) Directory path for persistent event store when the target is offline.
- `queue_limit` (Number) Maximum number of undelivered messages to queue.
- `tls` (Boolean) Whether to enable TLS for the NSQ connection.
- `tls_skip_verify` (Boolean) Whether to skip TLS certificate verification.
