# minio_notify_webhook (Resource)

Manages a webhook notification target for MinIO bucket event notifications. Webhook targets receive bucket events (object created, deleted, etc.) via HTTP POST requests.

MinIO supports publishing bucket events (object created, deleted, accessed, etc.) to HTTP webhook endpoints. This resource manages the server-level webhook notification target configuration. Once configured, use `minio_s3_bucket_notification` to subscribe specific buckets to this target.

Multiple webhook targets can be configured simultaneously to send events to different endpoints.

**NOTE:** Creating a new webhook target may require a MinIO server restart before it becomes fully active. The `restart_required` attribute indicates when this is necessary. Import is only supported for targets that are already active on the server.

**NOTE:** MinIO applies a new notification target only after a restart, so Terraform cannot tell on create whether a target with the same name is already stored on the server. Creating this resource over an existing target merges into it and takes it over, and destroying the resource then deletes it. Check first with `mc admin config get <alias> notify_webhook`, and import an existing target instead of creating it. See [#1438](https://github.com/aminueza/terraform-provider-minio/issues/1438).

See the [MinIO Webhook Notification documentation](https://min.io/docs/minio/linux/administration/monitoring/publish-events-to-webhook.html) for more details.

## Example Usage

```terraform
# Primary webhook target for bucket event notifications
resource "minio_notify_webhook" "primary" {
  name       = "primary"
  endpoint   = "https://webhook.example.com/minio-events"
  auth_token = var.webhook_token
  queue_limit = 100000
}

# Backup target with persistent queue for offline resilience
resource "minio_notify_webhook" "backup" {
  name       = "backup"
  endpoint   = "https://backup.example.com/events"
  queue_dir  = "/opt/minio/events/backup"
  comment    = "Backup webhook with persistent queue"
}

# Use the target in a bucket notification
resource "minio_s3_bucket_notification" "events" {
  bucket = "my-bucket"

  queue {
    queue_arn = "arn:minio:sqs::primary:webhook"
    events    = ["s3:ObjectCreated:*", "s3:ObjectRemoved:*"]
  }

  depends_on = [minio_notify_webhook.primary]
}
```

## Schema

### Required

- `endpoint` (String) HTTP(S) endpoint URL to send bucket event notifications to.
- `name` (String) Target name identifier.

### Optional

- `auth_token` (String, Sensitive) Authentication token for the webhook endpoint. MinIO does not return this value on read.
- `client_cert` (String) Path to the X.509 client certificate for mTLS authentication.
- `client_key` (String, Sensitive) Path to the X.509 private key for mTLS authentication.
- `comment` (String) Comment or description for this notification target.
- `enable` (Boolean) Whether this notification target is enabled.
- `queue_dir` (String) Directory path for persistent event store when the target is offline.
- `queue_limit` (Number) Maximum number of undelivered messages to queue.

### Read-Only

- `id` (String) The ID of this resource.
- `restart_required` (Boolean) Indicates whether a MinIO server restart is required.

## Import

Import is supported using the target name:

```shell
terraform import minio_notify_webhook.primary primary
```

Note: `auth_token` is not returned by the MinIO API. After import, this value will be empty in state until the next apply sets it from your configuration.
